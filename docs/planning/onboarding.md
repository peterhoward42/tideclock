# Tide Dial Onboarding Conclusions

## Core observation

The Tide Dial interface is intentionally designed to be interpreted gradually rather than explained exhaustively.

The opening experience should preserve:
- atmosphere
- curiosity
- instrument-like character
- visual scanning
- perceptual inference

while still preventing wildly incorrect first interpretations.

The goal is not complete immediate clarity.

The goal is to provide just enough conceptual stabilisation for the diagram to begin explaining itself.

---

# Key onboarding conclusions

## 1. Minimal conceptual anchoring is high leverage

The strongest explanatory material is the smallest and most diagram-linked set of concepts:

- Today’s 24 hour clock
- Green hand = time now
- Purple markers = tides and heights

These act as conceptual decoders rather than procedural instructions.

Once understood, users can infer:
- tidal rhythm
- next tide event
- spacing between events
- relationship between now and the next tide

without additional explanation.

---

## 2. Avoid large onboarding blocks

Longer explanatory copy risks reframing the experience as:
- a software tutorial
- an onboarding flow
- a specialist utility app

rather than:
- an instrument
- an appliance
- an observational object

The interface benefits from preserving some discovery and interpretive participation.

---

## 3. Seeded location messaging should remain separate

The seeded location message performs a different role from the conceptual key.

It explains:
- why this location is being shown
- that the location can later be changed

It should not be merged into the conceptual decoding material.

Preferred structure:

### Orientation layer
Showing tides for Looe, Cornwall  
Start here, then set your own location from the menu.

### Conceptual key
- Today’s 24 hour clock
- Green hand = time now
- Purple markers = tides and heights

This separation allows users to subconsciously distinguish:
- where the data comes from
- how the diagram works

---

# Portrait versus landscape on mobile

## Portrait mode conclusion

On mobile devices, portrait mode does not provide sufficient space for:
- rotation guidance
- conceptual explanation
- comfortable diagram visibility

simultaneously.

The diagram is already approaching:
- minimum practical text size
- minimum comfortable spatial separation

Attempting to add more onboarding material in portrait risks:
- clutter
- visual compression
- loss of atmosphere
- reduced legibility

Therefore:

## Portrait first visit behaviour on mobile

Show only the rotation encouragement.

Example:
> The diagram will be bigger if you turn your phone

This is valuable because landscape mode on mobile materially improves:
- readability
- comprehension
- scale
- visual calm
- instrument-like presence

The wording is successful because it is observational rather than commanding.

---

## Landscape first visit behaviour on mobile

Landscape mode on mobile should introduce:
- seeded location framing
- minimal conceptual key

because landscape provides enough room for:
- simultaneous reading and observing
- preservation of the diagram
- comfortable text sizing

---

# Overlay positioning conclusions

## Important insight

Not all occlusion costs the same.

### High-cost occlusion
- green hand
- current time region
- next tide marker

### Lower-cost occlusion
- peripheral empty regions
- areas outside the dial

The overlay should preserve visibility of the live explanatory elements.

---

## Final placement decision

Preferred onboarding overlay position:
- lower-left corner

Reasons:
- outside the primary dial geometry
- avoids the green hand region
- avoids the upcoming tide focus area
- preserves the smile-shaped silhouette
- maintains consistency between launches
- feels more like an instrument label than a modal dialog

---

# General design philosophy

The onboarding should feel closer to:
- a museum caption
- a label attached to an instrument
- gentle interpretive guidance

and less like:
- app onboarding
- task flow UI
- software instruction

The Tide Dial works best when users feel they are observing something already alive and in motion rather than configuring software before use.
